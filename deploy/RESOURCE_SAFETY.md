# 统计与录像分析的资源保护

- 统计 API 每个服务进程同时只执行一项查询，后台缓存预热使用同一个可重入锁。最多等 1 秒；繁忙时返回 HTTP 503 和 `Retry-After: 3`，避免无界堆积昂贵查询。
- 缓存重新检查位于计算锁内。同一条件的并发缓存请求不再重复计算；等待过久的请求直接收到可重试响应。
- 录像分析工作线程每 60 秒建立一次候选快照，依次消费；成功/失败解析后等待 5 秒。分析前重新检查文件、有效期和已有报告，保留解析后的数据库身份/有效期检查，不延长录像有效期。
- 没有改变 Linux 内核参数，也没有设置可能直接终止采集服务的内存上限。

## 验证

29 项相关测试通过：报警状态与持续时间（6）、统计并发（3）、录像分析（8）、网页服务（1）、抽卡事实（11）。`top100_pie.py` 的已有缩略图修改也纳入提交，并用生成图片进行渲染检查。

额外回归存在两个原有失败，已确认对应旧代码也有问题，不把它们报告为本次新增失败：
- `test_statistics_portal.py`：删除/排除统计来源后，已有缓存可能继续返回旧内容（9 项中 1 项失败）。
- `test_deck_pie.py`：大类归属的预期与当前 `deck_pie.py` 输出不一致（5 项中 1 项失败）；该模块在本次任务中未改变。

本次保护措施降低重复计算和扫描频率，但没有证据能保证消除所有内存压力；仍需观察真实流量下的可用内存及磁盘读取。
