# 萌卡 / YGOPro 观战录像订阅 QQ 机器人

在这台 Windows 电脑上订阅指定玩家。机器人发现对局后以观战身份进入，对局结束并把录像写完后建立索引。推送模式会把该玩家的录像目录链接发到 QQ 私聊；静默模式只在你来查询时给链接。

不接大模型。支持 QQ 私聊，以及可选的群内 @ 指令。`qq.allow_all_users` 为 `true` 时，所有用户都可以订阅和查询自己的录像；为 `false`（默认）时，仅允许授权名单里的 QQ 使用。订阅、查询和取消订阅均按发指令的 QQ 隔离。

## 和原来的观战脚本

观战、保存录像、查排名的逻辑来自 `D:\MyCardLibrary\ygopro\spectator\watch.py`，复制到本项目的 `bot\watch_core.py` 后做了适配。原来的脚本、虚拟环境和旧录像都没有改动，也没有搬过来。

游戏目录固定为配置里的 `ygopro_dir`，默认 `D:\MyCardLibrary\ygopro`。卡表、脚本仍从游戏目录读取。新的配置、登录状态、缓存、数据库、日志和新录像都在本项目的 `data` 目录。`D:\MyCardLibrary\ygopro\replay` 里已有的录像不会被读取、公开或删除。

多个排名条件会逐条判断。某一条不满足时，仍会检查后面的订阅，避免漏掉别的用户。

## 准备

### 现在的配置方式

配置完成后，日常只需双击根目录的 **`start-all.bat`**。它会复用已运行的 NapCat，否则打开 NapCat；等待工具号登录在线后，再启动录像程序。已经运行的新版录像程序也会复用。连续双击时不会重复启动。扫码等待最多五分钟，超时后完成登录、再次双击即可。首次更新后请先关闭旧录像程序窗口，再使用这个入口，NapCat 可以保持开着。

`start-all.bat` 是统一入口，两个运行窗口仍会保留，方便扫码和查看运行状态。`/health` 状态接口只返回程序是否运行，不包含账号、订阅或录像信息。公网分享隧道仍需另行配置。

1. 双击项目根目录的 `start-napcat.bat` 启动 NapCat，用工具号登录并启用正向 WebSocket 服务端。启动器会自动切换到正确目录，不要单独运行安装包 `bootmain` 文件夹里的模板。
2. 双击 `setup.bat`，按提示导入本项目的 NapCat 接口地址和 Token，填写日常发指令的 QQ 号和萌卡账号密码。密码输入时不显示。萌卡账号可先跳过以测试 QQ 回复。已有配置回车保留，旧文件会备份到 `data/config-backups`。
3. 双击 `doctor.bat`：检查 Token 是否一致、接口是否可连、工具号是否在线。该检查只读取状态，不发送 QQ 消息。网页登录密码不等于接口 Token，也不需要保存在机器人配置中。
4. 双击 `start.bat`，用授权的日常 QQ 私聊工具号发送“帮助”。窗口会显示接口已连接，或说明连接失败的原因并自动重试。

`start.bat`、`setup.bat`、`doctor.bat` 通过 `find-python.bat` 使用真实 Python，优先项目 `.venv`，其次 `D:\Anaconda3\python.exe`，不使用 WindowsApps 商店占位入口。`start.bat --check-python` 只验证 Python 和模块导入；`start-napcat.bat --check-path` 只验证 NapCat 路径，不启动 QQ。

使用 Anaconda 时，启动器会给当前窗口补上其 `Library\bin` 等运行路径，以便双击启动也能加载 SQLite DLL；无需事先打开 Anaconda Prompt，也不会修改系统环境变量。

暂未填写公网地址时可以先测试私聊和订阅；好友从外网下载仍需完成后面的隧道配置。`config.example.json` 是空白模板，实际账号和 Token 仅保存在本机 `config.json`。请勿分享 `config.json` 或 `data/config-backups`。

1. 安装 Python 3.9 或更高版本。不需要安装额外的包。
2. 准备一个专用的普通 QQ，用 NapCat 登录。
3. 在 NapCat 里打开 OneBot 11 正向 WebSocket，只监听 `127.0.0.1`，端口 `3001`。设置接口 Token。WebUI 密码另外设置，两者不要用同一个值。
4. 不要把 NapCat 的 `3001` 端口映射到公网。公网只通过下面的隧道访问分享页。

## 配置

把 `config.example.json` 复制为 `config.json`，再填写：

| 字段 | 作用 |
| --- | --- |
| `mycard.account` / `mycard.password` | 萌卡账号。留空时只能看到房间，不能进入观战 |
| `qq.access_token` | NapCat 正向 WebSocket 的 Token。留空时不连接 QQ |
| `qq.webui_password` | 只记在配置里，方便你自己登录 NapCat 网页。程序不使用它 |
| `qq.admins` / `qq.users` | 允许使用的 QQ 号。两边权限相同 |
| `share.public_base_url` | 外网能打开的分享地址。留空或填 `127.0.0.1` 时，链接只在本机有效 |
| `share.link_hours` | 链接有效小时数，默认 5 |

账号和 Token 请在本机填写。不要把 `config.json`、`data\session.json` 发出来。

## 启动

双击 `start.bat`，或在本目录执行：

```
python -m bot.main
```

启动时会说明账号、Token、WebUI 密码和公网地址是“已填写”还是“未填写”，不会打印具体内容。

## 指令

### 群里订阅，结果和录像私发

将工具号加入群，在配置的 `qq` 对象内设置 `"group_commands": true` 后重启录像程序。在群中用 QQ 的 @ 功能选中工具号，随后输入指令，例如：

```
@群萌新bot 订阅 "亚翁" 前100 推送
@群萌新bot 我的订阅
@群萌新bot 录像 "亚翁"
```

这里的 @ 必须是在 QQ 中选中的真实提及。普通聊天、@其他人和 @全体成员 不会触发。群里只回复“已私发”或失败提示，处理详情和录像链接发给指令发送者，后续新录像也只私发。不能用群号作为订阅者，也不能查询或取消其他群员的订阅。

群员建议先添加工具号好友。若 QQ 不允许陌生人私聊、且没有可用的临时会话，程序会在群里提示添加好友；已经登记的订阅会保留，用户之后可私聊查询。不会将私发失败的录像链接转发到群内。

在和机器人的私聊里发送。玩家名有空格时加上英文双引号。

```
帮助
订阅 "玩家名" 全部 推送
订阅 "玩家名" 前100 推送
订阅 "玩家名" 前100 静默
我的订阅
推送 "玩家名"
静默 "玩家名"
取消订阅 "玩家名"
录像 "玩家名"
```

“前100”表示只收录对手竞技排名在 1 到 100 的对局。排名查不到、未知或未上榜，都不算满足。也可以写“前50”这类正整数。

订阅时间按录像实际收到并保存的时间判断，不按每局开局时间判断。服务器在一场结束时补发第一、第二局录像，只要是在订阅之后保存的，两份都会收录；文件名仍沿用 watch 的每局开局时刻、玩家名和排名。旧版索引会从现有文件的保存时间补齐这个字段，不重命名或删除录像，也不改旧分享链接的快照及到期时间。

推送：新录像完整保存后，自动发送该玩家的目录链接。静默：继续观战和保存，只在查询时回复。已经订阅的玩家，直接发送完整玩家名也能查询。

同一个人被多位用户订阅时，合并成一次观战，同一房间只连接一次。每个人只看符合自己条件、且在自己订阅之后收录的录像。取消订阅不影响其他人。订阅变化只影响之后的选房，不打断已经开始的观战。

## 分享链接

链接使用随机令牌。从生成时起 5 小时后失效。失效后页面、单个下载和打包下载都会显示失效，本机录像不删除。再查询会生成新链接，旧链接的到期时间不变。

单文件下载保留本地 watch 风格的完整文件名和 `.yrp` 扩展名；打包下载为“玩家名 观战录像.zip”，压缩包内同样保留原录像文件名。

目录会写明收录时间范围和到期时间。里面是生成链接时已经存在、并且符合该用户条件的录像。之后新保存的录像要重新查询才会出现。

分享服务默认只监听 `127.0.0.1:8787`。它不提供 NapCat、管理接口、配置或数据库。

### 让好友从外网打开

本机地址不能给好友用。可以用临时隧道，例如 Cloudflare Tunnel：

1. 先启动机器人，确认本机能打开 `http://127.0.0.1:8787`。
2. 另开一个窗口执行：

```
cloudflared tunnel --url http://127.0.0.1:8787
```

3. 把命令输出的 `https://xxxx.trycloudflare.com` 写进 `share.public_base_url`，不要带路径，然后重启机器人。
4. 再在 QQ 里发送“录像 玩家名”，新链接才会带这个外网地址。

临时隧道重启后，主机名通常会变。已经发到 QQ 里的旧链接会打不开，需要重新查询。录像文件仍在 `data\replays`。如果换成固定域名的隧道，把新的 https 地址写入 `public_base_url` 即可，同样要重新生成链接。

## 测试

在项目目录执行：

```
python -m unittest tests.test_bot -v
python -m unittest discover -s tests -v
python bot\watch_core.py --self-test
```

已在本机通过的内容：

- 同一玩家被不同用户以不同排名订阅，宽松条件不会把不符合的录像发给别人
- 推送和静默
- 重启后订阅和已发送状态还在
- 用可控时钟检查满 5 小时的边界，以及目录、单文件、打包下载的过期
- 过期后录像文件还在
- 路径穿越和分享范围之外的文件不能下载
- 模拟的 NapCat 断线和发送失败会重试；断线期间不把待发送通知直接作废

这些是本地模拟和协议自检。还没有做的验证：

- 没有登录真实 QQ，也没有连接正在运行的 NapCat
- 没有进入萌卡的真实对局，也没有保存一盘真实观战录像
- 没有从外网打开分享页

## 现在还缺什么

实际配置以你本机的 `config.json` 为准。程序不会从旧观战目录复制账号或登录状态。运行 `doctor.bat` 可以检查当前还缺少什么。要真正跑起来，需要在本机填上：

1. `mycard.account` 和 `mycard.password`。没有它们就不能加入观战。
2. NapCat 的 `qq.access_token`，以及 `qq.admins` 或 `qq.users` 中的 QQ 号。没有 Token 时 QQ 不会连接；没有授权号码时，任何人都不能订阅。
3. 若要发给好友，安装并运行隧道，把得到的 https 地址写入 `share.public_base_url`。当前没有公网地址。

发送通知前会再次检查授权、推送开关、对手排名和订阅起始时间。断线期间修改了条件的旧通知，如果已经不符合当前条件，会跳过，不会向已撤销授权的用户发送链接。分享链接仍从生成时起五小时到期，录像继续保留。
