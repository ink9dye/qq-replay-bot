# 萌卡 / YGOPro 观战录像订阅 QQ 机器人

## 云端部署（2026-11 起）

线上 `101.201.108.188` 由四个 systemd 服务提供：`ygo-collector`（server-only 房间发现/派发 + 分享本体 `127.0.0.1:8789`）、`ygo-web`（统计后台 `127.0.0.1:8788`）、`ygo-qq`（QQ）、`ygo-cloud-watch`（云端观战客户端，单账号单间），NapCat 在 Docker。

远程观战已拆成 **server-only**：collector 只发现/派发，录制由云端/PC/安卓客户端完成。接口契约见 [docs/REMOTE_WATCH.md](docs/REMOTE_WATCH.md)，安卓开发指南见 [docs/ANDROID_CLIENT.md](docs/ANDROID_CLIENT.md)，每设备令牌与 QQ `令牌分发` 见 [docs/WATCH_DEVICE_TOKENS.md](docs/WATCH_DEVICE_TOKENS.md)，云端客户端单元见 [deploy/ygo-cloud-watch.service](deploy/ygo-cloud-watch.service)。

公网入口 `http://101.201.108.188:8787` 由 **nginx 1.24** 监听并反代到 `127.0.0.1:8789`：只放行 `/stats/*`、`/s/*`、`/health`、`/`，按 IP 限速（页面 10r/s、`/statistics/api/` 5r/s，burst 30/20）、单 IP 连接 20、请求头 10s 超时、上游读写 120s、`proxy_buffering off`。分享服务因此只绑回环，**公开链接格式不变**（仍是 `http://<服务器>:8787/stats/<token>`）。

配置随仓库：`deploy/nginx-ygobot-site.conf`、`deploy/nginx-ygobot-proxy.conf`；改完 `nginx -t && systemctl reload nginx`，不重启 collector。巡检脚本按 8787（nginx）/8789（share 本体）/8788 三个端口判断，并额外检查 `8787/health` 是否为 200（抓“nginx 在、上游挂”的 502）。

普通启动入口自动打开PyCharm并运行watch.py。独立名单与QQ订阅共用一个观战循环；Run窗口按停止即结束全部观战、QQ指令与网页服务，不保留另一个隐藏观战实例。已有统一实例时重复启动只打开文件，不重启观战。具体说明见 [PYCHARM_WATCH.md](PYCHARM_WATCH.md)。

## 单小局解析（第一阶段）

录像目录每个小局的「解析本小局」入口展示双方当局主卡与额外、推测卡组类型、实际先手、胜者及主卡／side用卡；额外卡组单独显示是否成功出场与出场次数，不展示行为明细。原录像可直接下载。解析页和JSON沿用原分享令牌、玩家范围与14天限制。首次打开后台独立重放，页面自动刷新；原生内核崩溃或超时不影响机器人。

新观战留存服务器的 `MSG_WIN` 小局结果（包括认输、超时）及用卡消息，写入相邻的 `.yrp.evidence.json`。胜者编号按录像内玩家顺序关联，不能按房间席位或文件名顺序关联。中途加入、重连、消息截断不冒充完整观战。完整观战事件可直接还原用卡；其他情况尝试使用 `runtime/ocgcore.dll` 及本机游戏卡库、脚本重放。第二、三小局上一局败方拥有先后手选择权，实际先手独立读取本小局回合事件，不能据此倒推上一局输赢。

旧录像缺少的胜负尝试匹配萌卡公开历史的双方与起止时间。整场2:0可推出两小局结果；整场2:1仅在已确认关联的完整三小局中，推出第三小局赢家等于整场赢家。缺局、重复或不唯一匹配时不推断。积分变化保留为辅助证据，不把整场积分变化当成每小局胜负。直接结果与推断结果分别标明来源。

用卡口径：发动卡片／效果，以及通常、特殊、反转召唤尝试，包含被无效的尝试；抽到、检索、送墓或盖放本身不算使用。事件归使用方，同一卡片同一方同一小局只产生一个后续统计样本；事件次数另列。非本方构筑卡片会单独注明。当前不做卡牌胜率汇总、不增加前100采集规则。

额外卡单独分类：只有收到对应召唤成功确认才算出场，召唤无效后离场不计。保存当局携带、是否出场和出场次数。后续出场率=成功出场小局数/当局额外带有该卡的有效小局数；出场胜率=出场且获胜小局数/出场且胜负已知小局数。先后手分别计算，同卡一局多次出场只形成一个小局样本。借用对方卡片不进入本方携带样本。原始事件只保留在JSON用于核验。

`.yrp.analysis.json` 保存解析结果、原录像SHA256、内核／卡库／已加载脚本指纹和证据。两类JSON随对应录像的14天清理一起删除，孤立文件也会清理。无法重放的录像明确标记，不能作为有效用卡统计样本。

命令行：`python -m bot.replay_analysis "录像路径.yrp" --history --output "结果.json"`。`--game-root` 指定只读游戏资源目录；`--context` 可提供已确认的整场小局关联。仅已验证0x1362双人录像和随附x64内核；重建内核使用 `python tools/build_replay_engine.py`，源码及Lua压缩包与许可证随附在 `vendor/replay-analysis/`（构建脚本会读取该目录）。

## 连接与消息稳定性

- `start-all.bat` 为统一入口，主程序和本项目NapCat都有单实例检查；已有NapCat时复用，登错号时提示手动切换，不自动终止QQ或重新登录。
- 普通接口断线按1、2、4、8、10秒逐步退避，最长10秒；连接稳定30秒后重置。75秒没有接口数据时重连。只重连OneBot，不反复重启QQ。
- 连续重试约25分钟仍连不上后停止自动重连；冷却写在 `data/qq-recovery.json`，重启程序后最多等10秒再试。想立刻恢复收发，双击 `resume-qq.bat`，或在工具号已在线时双击 `start-all.bat`（两者都只清冷却并重连接口，不登录、不扫码）；离线期间群消息不会补发，重连后需要重新发送指令。
- 所有文字、卡图、合并转发和自动通知共用发送队列，默认全局间隔1秒、同一群或私聊间隔2秒；相同成功回复15秒内去重。每人每会话请求间隔0.8秒，相同连续指令8秒内合并。队列有上限，避免积压后瞬间群发。这些是本程序减少打扰的参数，不是腾讯提供的安全频率。
- 同次检查发现的同一用户、同一玩家的多个录像合并成一条通知，待通知索引继续保存在数据库里。
- 只有QQ返回明确的验证、冻结、风控或发送限制文字时才进入手动处理状态；普通网络超时不会被当作账号风控。限制提示不会被自动绕过或验证，暂停状态保存在本机，重启程序也不会自动解除。
- 双击 `check-status.bat` 查看状态，冷却中会显示还有多少秒才自动重试。处理官方QQ提示后，双击 `resume-qq.bat` 只恢复接口连接并清除重连冷却，不会替你登录。换工具号时先修改 `qq.expected_self_id` 和对应账号的OneBot配置。

消息间隔可通过 `qq.send_interval_seconds`、`qq.destination_interval_seconds`、`qq.duplicate_reply_seconds`、`qq.request_cooldown_seconds`、`qq.duplicate_command_seconds` 调整。上述功能不能保证账号免受限制；QQ没有明确返回限制原因时，本程序不会声称已识别风控。

猜卡满5分钟无人猜对时，会在原群或原私聊自动公布答案和卡图，正常连接下每秒检查一次。猜对或手动揭晓会取消自动公布。QQ断线期间保留待公布答案，重连后补发；发送失败稍后重试，不转发到其他会话。题目和待公布队列仅在本次机器人进程中保存，程序重启会清空。

猜卡作答：当前群或私聊有未过期的题目时，直接发送完整卡名、其他译名、已配置外号或卡片密码，无需“猜卡答案”前缀，群内也无需@。群内同一题可由不同成员作答；其他群和私聊独立。仅已知卡名被当作答案，普通聊天不触发；原前缀形式继续兼容。

群内已启用固定格式指令免@：可直接发送“查卡 毁灭之黑”“选卡1”“历史 玩家名”“录像 玩家名”“订阅 玩家名 前100 推送”，也支持原来的@方式。普通聊天、只发送玩家名、仅@别人或@全体不会触发。候选按群和用户隔离，订阅仍属于发送指令的QQ。可通过 `qq.group_without_at=false` 恢复仅@方式；`qq.group_commands=false` 仍会关闭所有群指令。

临时公网链接最长有效5小时，提示中的到期时间是应用令牌的最晚失效时刻。localhost.run 临时地址没有固定保活时长；实际可用至令牌到期、电脑休眠、隧道断线或地址变化中最先发生的时刻，不能承诺通常能在线几小时。无法打开时重新发送“录像 玩家名”取得当前链接，录像仍按14天规则保存。

录像网页的竞技资料区同时显示该玩家的分数、排名和数据更新时间，不依赖是否解析出卡组。仅在打开该玩家网页或点击“刷新分数与排名”时查询萌卡，不定时遍历订阅名单。页面先展示缓存，再异步更新当前玩家，成功结果缓存60秒并存于 `data/cache/arena-profiles`；接口失败继续显示最近成功记录并注明时间，不把旧值伪装成实时值。首次从未成功同步的玩家显示等待首次同步，可点击刷新重试。查询接口与录像下载一样校验分享令牌和5小时有效期。

工具号绑定：`qq.expected_self_id` 固定为 `3528698561`。一键启动和每次接口重连都会核实实际登录账号；登错号时明确显示当前账号与正确工具号并暂停QQ收发。即使登错账号导致3001端口没有启动，也会通过本机NapCat管理页检测。此设置不代替手机扫码确认，请在手机QQ切换至工具号后扫码。

## 玩家竞技历史

发送 `历史 花无十日红`，返回北京时间当月竞技场次、胜率、当前分数、当前排名及积分走势图，无需订阅。群内按现有规则 @工具号 查询，直接在群内回复。只计竞技对局，平局计入总场数，娱乐对局不混入；公开数据缓存60秒。图的第0点为本月首场赛前积分，之后每点为一场结算积分。

走势图需要 matplotlib，本机 Anaconda 已安装。其他环境可执行 `python -m pip install -r requirements.txt`。图片随QQ消息发送，不生成长期公开文件；图片发送失败时仍返回统计。数据口径依据[萌卡公开接口源码](https://github.com/mycard/ygopro-arena-api/blob/master/routes/api.js)。

在这台 Windows 电脑上订阅指定玩家。机器人发现对局后以观战身份进入，对局结束并把录像写完后建立索引。推送模式会把该玩家的录像目录链接发到 QQ 私聊；静默模式只在你来查询时给链接。

不接大模型。支持 QQ 私聊，以及可选的群内 @ 指令。`qq.allow_all_users` 为 `true` 时，所有用户都可以订阅和查询自己的录像；为 `false`（默认）时，仅允许授权名单里的 QQ 使用。订阅、查询和取消订阅均按发指令的 QQ 隔离。

## 统一观战后端

项目根目录的 `watch.py` 是唯一观战实现，可独立运行，也由QQ前端调用。`bot/watch_core.py` 只是兼容旧导入路径的薄转接，与 `import watch` 指向同一个模块；不再从游戏目录导入Python代码。参考卡组资料 `reference_decks.json` 也已迁到本项目。

游戏目录仍为 `D:\MyCardLibrary\ygopro`，仅提供游戏资源。录像、卡组、缓存、登录和数据库统一在本项目 `data` 中：

```
qq-replay-bot/
  watch.py                 唯一观战后端，支持独立CLI
  reference_decks.json     参考卡组识别资料
  start-watch.bat           独立观战入口
  start-all.bat             QQ模式入口
  bot/                     QQ指令、订阅、分享与索引前端
  data/
    watch-config.json      独立观战配置（原名单和设置已迁入）
    replays/               按玩家分目录的录像
    decks/                 观战卡组
    cache/                 卡表缓存
    session.json           萌卡会话
    bot.sqlite3            QQ订阅、索引、通知与分享快照
```

独立运行：双击 `start-watch.bat` 或运行 `python watch.py`，不需要QQ、NapCat或隧道。`python watch.py --name "雨雨雨1"` 可临时指定玩家；`--check-config` 只检查路径和配置，`--self-test` 只做本地自检。旧路径 `spectator/watch.py` 仅作兼容跳转，后续应在新项目中维护代码和配置。

QQ模式继续双击 `start-all.bat`。所有已订阅玩家出现即观战，不因对手排名跳过；“前N”只限制推送和录像下载。卡组展示使用该玩家最近的全量观测，并与录像下载分开保存快照，不会给用户提供不符合排名条件的录像文件。独立与QQ模式是同一后端的两种启动方式，日常运行QQ模式即可。

用户已确认：录像和卡组保存满14天自动删除。两种模式共用 `retention_policy.py` 和后端物理清理函数，QQ前端同步数据库索引。查询、下载和解析在到期边界立即排除录像；清理任务按最近到期时间唤醒，最多每60秒重新发现文件，删除失败每秒重试。到期删除录像、解析JSON、胜负证据和关联索引，不再仅每小时清理。系统暂停或文件被占用时无法保证物理删除的实时性，恢复运行后补清理。

保留期以原始保存时间计算；重新导入同一份已索引录像、重新解析和卡组重新分类不续期。迁移只延长尚存文件的保留期，不恢复旧7天策略已经删除的数据，不代表已积累完整14天样本。分享令牌仍最长有效5小时。`/health` 的 `retention_days` 可确认当前运行进程使用的策略。

完整差异、合并选择和备份说明见 [WATCH_MERGE_COMPARISON.md](WATCH_MERGE_COMPARISON.md)。

## 准备

### 现在的配置方式

配置完成后，日常只需双击根目录的 **`start-all.bat`**。它会复用已运行的 NapCat，否则打开 NapCat 并用已保存的会话自动登录（首次登录或会话过期才需要扫码）；等待工具号登录在线后，再启动录像程序。已经运行的新版录像程序也会复用。连续双击时不会重复启动。等待最多五分钟，超时后完成登录、再次双击即可。首次更新后请先关闭旧录像程序窗口，再使用这个入口，NapCat 可以保持开着。

`start-all.bat` 是统一入口，两个运行窗口仍会保留，方便扫码和查看运行状态。`/health` 状态接口只返回程序是否运行，不包含账号、订阅或录像信息。开启 `share.quick_tunnel` 后，免费公网分享会随录像程序自动连接。

1. 双击项目根目录的 `start-napcat.bat` 启动 NapCat，用工具号登录并启用正向 WebSocket 服务端。已配置快速登录：登录过一次后会自动登录，不需要每次扫码。启动器会自动切换到正确目录，不要单独运行安装包 `bootmain` 文件夹里的模板。
2. 双击 `setup.bat`，按提示导入本项目的 NapCat 接口地址和 Token，填写日常发指令的 QQ 号和萌卡账号密码。密码输入时不显示。萌卡账号可先跳过以测试 QQ 回复。已有配置回车保留，旧文件会备份到 `data/config-backups`。
3. 双击 `doctor.bat`：检查 Token 是否一致、接口是否可连、工具号是否在线。该检查只读取状态，不发送 QQ 消息。网页登录密码不等于接口 Token，也不需要保存在机器人配置中。
4. 双击 `start.bat`，用授权的日常 QQ 私聊工具号发送“帮助”。窗口会显示接口已连接，或说明连接失败的原因并自动重试。

`start.bat`、`setup.bat`、`doctor.bat` 通过 `find-python.bat` 使用真实 Python，优先项目 `.venv`，其次 `D:\Anaconda3\python.exe`，不使用 WindowsApps 商店占位入口。`start.bat --check-python` 只验证 Python 和模块导入；`start-napcat.bat --check-path` 只验证 NapCat 路径，不启动 QQ。

使用 Anaconda 时，启动器会给当前窗口补上其 `Library\bin` 等运行路径，以便双击启动也能加载 SQLite DLL；无需事先打开 Anaconda Prompt，也不会修改系统环境变量。

暂未填写公网地址时可以先测试私聊和订阅；好友从外网下载仍需完成后面的隧道配置。`config.example.json` 是空白模板，实际账号和 Token 仅保存在本机 `config.json`。请勿分享 `config.json` 或 `data/config-backups`。

1. 安装 Python 3.9 或更高版本。不需要安装额外的包。
2. 准备一个专用的普通 QQ，用 NapCat 登录。
3. 在 NapCat 里打开 OneBot 11 正向 WebSocket，只监听 `127.0.0.1`，端口 `3001`。设置接口 Token。WebUI 密码另外设置，两者不要用同一个值。
4. 不要把 NapCat 的 `3001` 端口映射到公网。公网只通过下面的隧道访问分享页。

## 配置

把 `config.example.json` 复制为 `config.json`，再填写：

| 字段 | 作用 |
| --- | --- |
| `mycard.account` / `mycard.password` | 萌卡账号。留空时只能看到房间，不能进入观战 |
| `qq.access_token` | NapCat 正向 WebSocket 的 Token。留空时不连接 QQ |
| `qq.webui_password` | 只记在配置里，方便你自己登录 NapCat 网页。程序不使用它 |
| `qq.admins` / `qq.users` | 允许使用的 QQ 号。两边权限相同 |
| `share.public_base_url` | 外网能打开的分享地址。留空或填 `127.0.0.1` 时，链接只在本机有效 |
| `share.quick_tunnel` | 设为 `true` 时自动使用 localhost.run 临时公网地址，忽略手填的公网地址 |
| `share.link_hours` | 链接有效小时数，默认 5 |

账号和 Token 请在本机填写。不要把 `config.json`、`data\session.json` 发出来。

## 启动

双击 `start.bat`，或在本目录执行：

```
python -m bot.main
```

启动时会说明账号、Token、WebUI 密码和公网地址是“已填写”还是“未填写”，不会打印具体内容。

## 指令

### 群内回复指令，推送订阅的新录像私发

将工具号加入群，在配置的 `qq` 对象内设置 `"group_commands": true` 后重启录像程序。在群中用 QQ 的 @ 功能选中工具号，随后输入指令，例如：

```
@群萌新bot 订阅 "亚翁" 前100 推送
@群萌新bot 我的订阅
@群萌新bot 录像 "亚翁"
```

这里的 @ 必须是在 QQ 中选中的真实提及。普通聊天、@其他人和 @全体成员 不会触发。指令确认、帮助、查询结果和主动查询的录像链接都在原群回复；只有设为“推送”的订阅，其后续新录像通知才私发给订阅者。不能用群号作为订阅者，也不能查询或取消其他群员的订阅。

推送订阅建议先添加工具号好友。群内指令不要求能私聊；群回复失败也不会改成私聊。自动录像推送仅走私聊，失败时按原逻辑保留重试，不转发到群内。若想让主动查询的录像目录只给自己看，请私聊发送录像指令。

以下指令可私聊发送，也可在已启用群指令的群中真正@工具号后发送。玩家名有空格时加上英文双引号。

```
帮助
订阅 "玩家名" 全部 推送
订阅 "玩家名" 前100 推送
订阅 "玩家名" 前100 静默
我的订阅
推送 "玩家名"
静默 "玩家名"
取消订阅 "玩家名"
录像 "玩家名"
```

“前100”表示只收录对手竞技排名在 1 到 100 的对局。排名查不到、未知或未上榜，都不算满足。也可以写“前50”这类正整数。

收录时间按录像实际收到并保存的时间判断，不按每局开局时间判断。服务器在一场结束时补发第一、第二局录像，两份都会收录；文件名仍沿用 watch 的每局开局时刻、玩家名和排名。旧版索引会从现有文件的保存时间补齐这个字段，不重命名或删除录像，也不改旧分享链接的快照及到期时间。

推送：新录像完整保存后，自动发送该玩家的目录链接。静默：继续观战和保存，只在查询时回复。已经订阅的玩家，直接发送完整玩家名也能查询。

同一个人被多位用户订阅时，合并成一次观战，同一房间只连接一次。录像在同一玩家的订阅者之间共享，每个人只看符合自己条件、且在最近14天收录的录像。取消订阅不影响其他人。订阅变化只影响之后的选房，不打断已经开始的观战。

## 分享链接

录像页采用响应式卡片布局，按真实整场观战分组，同一场的多局录像放在一起。每场和每局注明双方玩家与卡组类型，下载文件名也附带双方卡组类型；磁盘中的原录像不重命名。旧场次仅在 watch 已有YDK与唯一录像组的主卡、额外、side完全一致时回填分组。

网页上方附带“最近观战卡组”及 OURYGO 展示链接，标题格式为“玩家名 · 卡组类型（多久前） · 竞技分数”。同场卡组直接复用 watch 的 `sided_decks`：保留收到的最早一局主卡和额外，后续换入的卡按最大观测张数推断为side。可再从主卡卡片及每张数量完全相同的历史场次补充side，同卡取最大张数，不跨场累加；不要求卡片排列顺序相同。主卡构筑变化后不继承旧side。补充来源同样受该链接快照、对手排名和十四天范围限制，不能使用其他用户无权查看的录像。推断结果不保证是完整副卡组，网页注明来源。

卡组类型复用 watch 的卡名识别算法，并注明为推测；主卡、额外、side 卡片直接内嵌网页展示，另附 OURYGO 链接。分数取萌卡公开竞技接口的 `pt`，不将排名当分数，最多缓存5分钟，无法读取时明确显示暂不可用。没有可解析数据时显示尚未解析，不使用其他玩家的卡组。无需新增卡组指令。

卡组链接兼容 OURYGO 的 v1 格式；非标准卡片密码超过27位时使用站点支持的 v0 格式，避免截断。OURYGO 链接本身包含卡组数据，取得后不会随本机录像页的5小时期限失效。

录像只提供最近14天保存的内容，仍须符合各自订阅的对手排名条件。查询、推送、目录、单个下载和打包下载都会检查这十四天范围。保存满14天后，即使此前生成的链接还没到期，也不再提供该录像；超过14天的录像和卡组会被自动删除。

每个QQ用户的每位玩家分别拥有订阅条件、推送开关、录像目录及链接。取消或修改一个玩家不会影响其他玩家，单个玩家的下载链接与压缩包不会混入另一个玩家的文件。

链接使用随机令牌。从生成时起 5 小时后失效。失效后页面、单个下载和打包下载都会显示失效，本机录像不删除。再查询会生成新链接，旧链接的到期时间不变。

每场对战一个「下载本场全部录像」按钮，点击后依次下载本场全部录像（多个 `.yrp`，不是 zip），每份保留本地 watch 风格的完整文件名和 `.yrp` 扩展名；顶部「打包下载全部录像」仍为“玩家名 观战录像.zip”，压缩包内同样保留原录像文件名。

目录会写明收录时间范围和到期时间。里面是生成链接时已经存在、并且符合该用户条件的录像。之后新保存的录像要重新查询才会出现。

分享服务默认只监听 `127.0.0.1:8787`。它不提供 NapCat、管理接口、配置或数据库。

### 让好友从外网打开

#### 免费自动临时地址

设置 `share.quick_tunnel` 为 `true` 后，录像程序通过 Windows 自带的 OpenSSH 客户端自动连接 localhost.run，并读取当前的 `https://随机名称.lhr.life` 临时地址，无需注册、购买域名或每次手改配置。使用前应同意将录像分享服务接到该第三方服务。本机已确认具备 OpenSSH。它只转发 `127.0.0.1` 的录像 HTTP 服务，QQ 和 NapCat 管理接口不会通过该隧道公开，不读取个人 SSH 配置、私钥或代理。

日常仍只双击 `start-all.bat`。隧道没连通时不会把不可用的本机地址推送给好友，待发送通知会保留；恢复后继续发送。后台连接断开后会自动重试，重启录像程序时会复用已有连接。录像服务关闭两分钟后，后台连接也会退出。免费域名会定期改变，重新连接或重启电脑也可能换地址，需要重新查询录像链接。关闭录像程序或电脑、断网时，外网无法访问。五小时是每条分享令牌的有效期，临时域名没有五小时在线保证；到期后录像继续保留。隧道日志在 `data/logs/tunnel.log`，本机状态接口只监听 `127.0.0.1:47879`。

服务说明：[免费套餐限制](https://localhost.run/docs/forever-free/)、[SSH 参数](https://localhost.run/docs/cli/)。

#### 手动或固定地址

本机地址不能给好友用。可以用临时隧道，例如 Cloudflare Tunnel：

1. 先启动机器人，确认本机能打开 `http://127.0.0.1:8787`。
2. 另开一个窗口执行：

```
cloudflared tunnel --url http://127.0.0.1:8787
```

3. 把命令输出的 `https://xxxx.trycloudflare.com` 写进 `share.public_base_url`，不要带路径，然后重启机器人。
4. 再在 QQ 里发送“录像 玩家名”，新链接才会带这个外网地址。

临时隧道重启后，主机名通常会变。已经发到 QQ 里的旧链接会打不开，需要重新查询。录像文件仍在 `D:\pythons\qq-replay-bot\data\replays`。如果换成固定域名的隧道，把新的 https 地址写入 `public_base_url` 即可，同样要重新生成链接。

## 现在还缺什么

实际配置以你本机的 `config.json` 为准。程序不会从旧观战目录复制账号或登录状态。运行 `doctor.bat` 可以检查当前还缺少什么。要真正跑起来，需要在本机填上：

1. `mycard.account` 和 `mycard.password`。没有它们就不能加入观战。
2. NapCat 的 `qq.access_token`，以及授权名单或 `qq.allow_all_users=true`。没有 Token 时 QQ 不会连接；未开放所有人且没有授权号码时，任何人都不能订阅。
3. 若要发给好友，启用已同意使用的自动临时隧道，或把自己的固定 https 地址写入 `share.public_base_url`。

发送通知前会再次检查授权、推送开关、对手排名和订阅起始时间。断线期间修改了条件的旧通知，如果已经不符合当前条件，会跳过，不会向已撤销授权的用户发送链接。分享链接仍从生成时起五小时到期，录像继续保留。


## 百鸽查卡

重启录像程序后，授权用户可私聊发送：

- `查卡 青眼白龙` / `ck 青眼白龙`：精确卡名命中时发送卡图、效果和百鸽链接。
- `查卡 闪刀`：允许不完整卡名，搜索能力由百鸽提供，结果每页最多5张。
- `选卡 1`：查看自己最近候选中的第1张；候选5分钟后过期。
- `查卡下一页`：查看后续候选。以每次显示的序号为准。
- `查卡 89631139`：使用卡片密码查询。支持效果关键词、多种译名；错字纠正不保证命中。

使用现有 QQ 授权名单；群内仍须启用群指令并真正 @ 工具号，结果在原群回复。普通聊天和裸数字不会触发选卡，也不发送任何主动查卡通知。卡图发送失败时退回文字及图片链接。

内置少量外号：`灰`→灰流丽、`泡影`→无限泡影、`g`→增殖的G。可编辑 `data/card_aliases.json`（UTF-8 JSON对象），例如：

```json
{
  "小灰": "灰流丽",
  "白龙": "89631139"
}
```

外号表每次搜索读取，无需重启；值可为卡名或密码。自定义同名外号覆盖内置项。将外号映射为正式完整卡名或密码，可以减少歧义。

搜索使用 `https://ygocdb.com/api/v0/`，单次请求超时8秒，结果在内存缓存1小时，上限128项；重启后清空。无需新依赖。搜索失败会提示重试，不影响订阅和录像。卡图由百鸽公开CDN提供。接口说明：https://ygocdb.com/api 。


## 随机一卡、猜卡与 OCG 禁限

| 指令 | 功能 |
| --- | --- |
| `随机一卡` | 从百鸽卡库随机抽一张，返回卡图和效果，排除衍生物；格式与 `查卡` 相同，含卡包与发售日期 |
| `猜卡` | 根据隐藏卡名的类型、效果猜卡；每人一题，5分钟有效 |
| `猜卡答案 完整卡名` | 作答，也支持其他译名、外号或密码；答错可继续 |
| `揭晓猜卡` | 查看答案和卡图，结束本题 |
| `禁限 OCG 灰流丽` | 查单卡当前OCG禁限状态及表的生效日期；可用外号或密码 |
| `禁限表 OCG` | 合并转发完整的当前已生效OCG禁限表 |
| `禁限表 OCG 2020-04` | 查2020年4月1日已生效的最近一期表 |

禁限默认OCG，可省略 `OCG`。暂不接入TCG、MD、简中独立禁限表。历史查询按指定月份1日判断；没有新一期时返回此前仍有效的一期。数据源缺失的历史不推断，未来月份不作为历史查询。当前表按北京时间当天判断，已公布但未生效的表不会被当作当前表。

单卡未列入表时显示无限制；这不判断是否已在OCG发售或具有赛事使用资格。禁限记录使用官方CID关联卡库，避免将卡片密码当成CID。来源 https://ygocdb.com/api 。禁限网络数据内存缓存1小时。

卡库缓存在 `data/cache/baige/cards.json`；首次使用下载，之后每天检查百鸽MD5，只有数据变化才重新下载。下载先核对内容MD5，使用临时文件替换缓存，不修改游戏目录的卡库。网络获取失败会提示重试，不拿缺失数据返回无限制。

猜卡采用文字提示，完整卡名会被隐藏；答案接受卡库已有的其他译名和自定义外号。所有功能沿用原授权名单，群内需真正@工具号且结果在原群回复；每群共用一题，授权群员都可@工具号作答或揭晓。私聊题目则按用户隔离，群之间以及群与私聊之间互不影响。不会主动发游戏或禁限通知。裁定查询未加入。
