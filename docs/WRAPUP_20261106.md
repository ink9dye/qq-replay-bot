## 2. 接口变更摘要

### 2.1 `/replay-api`（PC 观战客户端用）

- `GET /replay-api/ping`、`/matches`、`/match`、`/match.zip`；v1 的 `/search`、`/download` 保留兼容。
- 筛选：`player`/`opponent`（玩家名，双侧可填）、`self_deck`/`opponent_deck`（卡组，**以对战为单位、子串匹配**）、
  `self_rank`/`opponent_rank`（全部/前100，取当前榜单）、`from`/`to`、分页。
- 下载单位是整场：一个文件夹（`日期_玩家A_vs_玩家B/`），含每局 `.yrp`、每局 `N_game.json`、整场 `match.json`；
  `raw=1` 才附带原始证据。
- 全局限速 200 KiB/s（≈1.6 Mbps），并发 4；全库 `.yrp` 约 6.5 MB。
- 场次来源三级回退：`replay_sessions` → 上传账本 `capture` → 证据 JSON 尾部。
  `replay_sessions` 自 2026-11-03 21:19 后停更（本地观战停用），根因与回填方案见 R7。

### 2.2 `/query-api/player/名称/decks`（查询客户端用）

- 返回玩家最新观测构筑：`cards` 现在含 `partition=main/extra/side`，每张有 `code`/`copies`/`name`。
- **Side 是推测**：来自构筑页同一套 `statistics_build_detail.infer_side`（同场多局差异 + 收敛），
  每张带 `inferred: true`、`copies`、`sources`；顶层 `side_inferred={complete, conflict, reason, order}`。
- `completeness.side` 仍为 false：数据库 `stat_build_cards` 没有真实 side 分区，不能当真实副卡组。
- 实现用 collector 进程内只读连接计算（timeout 15 秒），不走门户 `/build-detail`——门户那边 3 秒读锁，晚高峰会 503。

### 2.3 `/statistics/api/recordings`（统计网页录像筛选）

- `player` 参数保留（URL/API 可用），但网页上的「我方玩家名」输入框已于 18:40 撤掉；
- 卡组条件恢复为**子串匹配**（`deck_matches(contains)`），此前被旧基线覆盖成精确匹配。

## 5. 限制与遗留

1. **Side 是推测**，不是真实副卡组；`side_inferred.complete` 生产上目前都是 false。
2. **R7 场次表回填**未做：A 入库回填 / B 一次性回填 / C 只读兜底，待决策（D8）。
3. 另一对话的“统计查询候选包”未部署：其 filters 基于旧基线，直接 scp 会回退卡组子串匹配，需 rebase 到新 master 后再上。
4. 安卓端未接 `/replay-api`；接口仍是 HTTP 无 TLS。
5. 录像库令牌等于全库读权限，泄露需 `令牌分发 吊销`。
6. 网页录像筛选的 `player` 参数没有 UI 入口，只能拼 URL 使用。
