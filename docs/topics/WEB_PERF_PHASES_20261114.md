# 录像分阶段观测与轮转读取（2026-11-14，已上线）

## 目的与边界

补齐旧报告漏读实际logrotate的`.1/.gz`，并把录像计算按高层阶段记录。仅观测：不改变查询、排序、首局、卡片条件、权限、锁策略、缓存TTL或后台刷新/采样频率；不添加线程、依赖或常驻探针，不记录SQL文本、玩家、卡名、digest、请求参数或凭据。

`statistics_recording_filters.py`增加总计算、样本选取、对手上下文、命名、事实读取与处理、起手证据合并、最终筛选和排序计时；`statistics_match_identity.py`增加身份读取/解析计时。复用现有请求ContextVar和worker日志。调用结果及异常原样传递；无上下文时装饰器直接调用原函数。两业务文件去掉新增观测包装后，与实际生产基线AST一致。

`recordings_total_ms`是整体；`identity_read_ms`属于样本选取/命名内部的嵌套子项，不能重复相加。样本选取仍包含资格SQL、源文件检查和身份处理，facts/opening包含SQL获取、遍历、合并；**不能当成纯SQL或纯CPU计时**。缺字段可能是旧代码、未执行可选阶段或提前失败，仍为未知。缓存响应不会产生新的计算阶段。

## 日志读取

访问及worker日志自动展开当前文件、最多8份编号轮转和旧`.previous`；同编号同时有`.1`/`.1.gz`时优先普通文件，按物理文件身份去重。不按相同JSON行去重，以免删掉合法的重复请求。每个普通文件最多读末尾32MiB；gzip最多读取前32MiB解压内容，达到上限标记截断，坏gzip标记read_error。报告列出实际读取文件、JSON记录数、有效时间范围和截断/错误状态。没有日志不表示没有慢请求。

报告筛选仍按原窗口时间；读到的文件覆盖范围可能比窗口大。每文件限制意味着不保证完整历史，不能把计时累计当作可消除的CPU时间。资源关联和QQ计数不改。
